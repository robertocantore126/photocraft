# UX fixes, Fotox imports and brush plug-ins (2026-10-11)

Branch `feat/ux-fixes-2026-10-11` (from `feat/action-trace` cb36c7c9), worktree `E:\pc-fix`.

## Rob's list

| # | Request | What changed |
|---|---|---|
| 1 | Dragging a layer to the top/bottom edge of the Layers panel scrolls the list until the drop | `panels::layer_drag_autoscroll`: within 32 px of the edge (or past it) the list scrolls, faster the further out the pointer is (150 px/s at the edge up to 8000 px/s), and keeps repainting while the pointer rests there. Rows scrolled out of view no longer take the drop. |
| 2 | After Convert to Smart Object other actions did nothing; rasterizing fixed it | Not reproduced: in the engine and through the real canvas (egui harness) move, brush on another layer and transform all work after the conversion. What does silently nothing is painting on the Smart Object itself (status-bar error only). Now, as in Photoshop, painting / filling / a gradient on a Smart Object, type, shape or fill layer opens "This Smart Object must be rasterized before proceeding… Rasterize?" (OK rasterizes). Rob's trace of 2026-10-10 18:25 shows Move-tool drags producing no command at all after the conversion: if it happens again, a Save trace right after it would show which path drops the input. |
| 3 | Auto-Select and Show Transform Controls on by default | `ToolOptions` defaults (`move_auto_select`, `move_show_transform` = true). |
| 4 | The transform preview must show the layer where it is in the stack, not on top | `transform_tool::in_place_doc`: the box's transform is applied to the layer in a copy of the document (`transform_cmds::transformed_document`, bilinear) and the canvas shows that, with damage tracked per update like the live stroke (only what moved recomposites). Updates slower than 40 ms are redone at most every 100 ms during a drag and always on release. Warp and Transform Selection keep the mesh overlay; `PHOTOCRAFT_TRANSFORM_ON_TOP=1` brings the old preview back. |
| 5 | Noise filter: use Fotox's | `algo/noise.rs::add` is Fotox's Add Noise: same hash, amount 100 % = ±100 % (uniform) / σ = ½ amount (Gaussian, Box–Muller), monochromatic shares one value, clamped to 0..1. Twice as strong as before at the same amount. |
| 6 | A tool remembers its last brush and size | `paint_mouse::sync_tool_smoothing` now saves and restores the whole brush (preset tip, size, hardness, opacity, flow, smoothing…) per tool, brush plug-ins included; colours stay the session's. |
| 7 | A click outside the object commits the change | Already true for the transform box; added: a click outside the warp mesh commits a Warp, and picking another tool or another layer in the Layers panel applies the transform. |
| 8 | Fotox's Object Selection and lasso | New crate `photocraft-ml` (ONNX Runtime, load-dynamic, DirectML first) with BiRefNet and EfficientSAM, using the models and runtime already in `%LOCALAPPDATA%\Fotox\models` (`PHOTOCRAFT_MODELS` overrides). `select.object` takes a box, a click (`point`) or a `lasso`; Select Subject uses BiRefNet too. Edge refinement with Select and Mask's guided filter. Options bar: Mode Rectangle/Lasso, Model BiRefNet/EfficientSAM, Sample All Layers. Without models it falls back to GrabCut (box only). Models load in the background the first time the tool is picked, not at start. `PHOTOCRAFT_AI=0` turns the AI off. Lasso: new **Magnetic Lasso** (live-wire on edges, Width/Contrast/Frequency, click anchors, Backspace, Enter/double-click/first anchor closes); Lasso: ⌥ during the drag draws straight segments; Polygonal Lasso: double-click closes, Backspace removes the last point. |
| 9 | Free Transform corners like Photopea | The chain in the options bar (Keep Aspect Ratio) now drives corner drags: on (default) proportional, ⇧ free; off the reverse. The proportional factor is the pointer's projection on the diagonal, so dragging a corner down or inwards shrinks it. Edges always scale one axis. |
| 11 | Color Range from one layer | Select › Color Range has **Sample: Current Layer (name) / All Layers** (default the layer, remembered). The layer is read alone, the parts other layers cover included; a Smart Object, type, shape or group is rendered alone (it used to fall back to the composite). `select.colorRange` also takes `"layer": id`. The Magic Wand's single-layer sampling handles those layers the same way. Test `engine/tests/color_range_layer.rs`. |
| 10 | Import Fotox's plug-in system for new tools | Brush plug-ins with Fotox's ABI (`fx_manifest`/`fx_alloc`/`fx_rect`/`fx_gray`) on PhotoCraft's wasmi sandbox (`photocraft_plugins::brush`, SIMD enabled): Fotox's `.wasm` files load unchanged. The stroke engine calls the plug-in per dirty tile (`photocraft_paint::PixelOp`), with `max` accumulation and the feather tip from the manifest's `brush` hints. Folder `%APPDATA%\Photocraft\plugins` (Fotox's plug-ins are copied in the first time), watched twice a second; a `.rs` there is built by PhotoCraft (`engine/brush_script.rs`, needs `cargo` + `wasm32-unknown-unknown`), errors go to `<name>.errors.txt`. Each plug-in is a tool in its slot's flyout with the option bar from its manifest. Edit ▸ Brush Plug-ins ▸ Open Plug-ins Folder / Reload. SDK and the three erasers in `plugins/`, `AI-PROMPT.md` adapted. |
