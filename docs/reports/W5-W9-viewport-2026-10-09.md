# W5 and W9 viewport implementation — 2026-10-09

Isolated worktree E:\pc-ps-c, branch perf/w9-preview, base be4168c. Depends on lane A job/progress APIs, lane B CPU mips and exact surface-bounds metadata, and the bounded GPU filter implementation.

The default canvas composes a viewport rectangle plus a margin into a viewport-sized GPU texture. Each UI view owns a separate output texture; source document coordinates are retained while encoding the cropped output. GPU effect completion invalidates every viewport reading the same source. Memory preferences still set the compositor budget. Below 50% zoom, display-only documents contain native CPU mip tiles over the visible rectangle plus effect and mask-feather halos. Derived bounds preserve layer-aligned effect and fill anchors. The CPU fallback similarly renders a bounded viewport from those mips. Canvas/window/document caches are owned by the app and pruned when documents close. The CPU viewport path calls the bounded lower-stack PrefixCache for supported top-level boundaries; PHOTOCRAFT_CPU_PREFIX_CACHE=0 restores normal CPU stack rendering. Navigator images on CPU and GPU paths read CPU mip documents at an appropriate thumbnail level. PHOTOCRAFT_VIEW_COMPOSE=0 restores the earlier canvas path. A larger-than-normal viewport increases the mip level to keep display textures bounded.

For Gaussian Blur, Box Blur, Motion Blur, Unsharp Mask and High Pass on raster layers, previews filter only the visible target area using the algorithm's exact halo and original canvas boundary rules. A native worker runs one request at a time; changing parameters cancels the current request and replaces the single queued request. Results are displayed only for the latest parameters, document revision, active layer and viewport. The input mip proxy persists across slider changes while it covers the new halo. Selection mixing and document color/depth data remain in the ordinary compositor path. The worker attempts the cached GPU filter pipelines and falls back to the CPU algorithm on unsupported devices, formats or work sizes. Wasm runs inline and uses the CPU filter. PHOTOCRAFT_FILTER_VIEW=0 restores the persistent whole-document proxy; PHOTOCRAFT_GPU_FILTERS=0 disables GPU kernels.

Changes: compose/mip_view.rs and bounds.rs; ui-egui/canvas.rs, filter_dialog.rs, filter_region.rs, gpu_canvas.rs and app cache fields. See w9-w10-preview-brush.md for independent brush work.

Verification: native cargo check -p photocraft-ui-egui passed on the final viewport/prefix/cache/filter code (the later asynchronous-open tab fix is the lane A commit). Full native build, wasm and layering checks are delegated to the root integration branch. No tests, benchmark, timing measurements or visual comparisons were added or run, following the user's instruction. GPU pixel tolerance and live UI behavior are not claimed verified.

Still open: broadening viewport filter previews beyond the five supported local filters/raster layers, and optional W11 foreground caching. Other filter dialogs retain their existing proxy path. Destructive command jobs keep the CPU oracle; GPU acceleration is currently wired to preview workers.

Limits: a zoomed-out viewport filter proxy contains only the view and halo; its Navigator uses the complete committed document until Apply. Cold missing CPU mips still compute synchronously on the canvas path; the cache avoids repeated work but first-view latency has not been measured. No GPU readback pixel-tolerance claim is made. W11 is deliberately deferred as optional; backdrop-dependent blend modes/groups are not precomposed.

Hidden layers and hidden group subtrees retain their tree metadata without preparing source/mask mip tiles. Their effects do not inflate the viewport halo. A filter dialog on a hidden target (including a visible target inside a hidden parent) uses the existing full proxy path, so the viewport helper never filters an unscaled hidden surface.
