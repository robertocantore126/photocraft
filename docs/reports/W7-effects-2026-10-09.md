# W7: deferred effect inputs (2026-10-09)

The live GPU canvas can build CPU layer shapes and exact distance fields on two dedicated native workers. GPU texture uploads and map programs remain on the render thread. The compositor used by export stays synchronous by default, so an export never captures a partially settled preview.

Changed files: `crates/gpu/src/fx_jobs.rs`, `crates/gpu/src/lib.rs`, `crates/ui-egui/src/gpu_canvas.rs`.

The queue has eight request slots, two reply slots, at most twelve tracked requests and a 256 MiB combined input reservation. Each request is keyed by document, layer/cell, region, source tile identities and effect program settings. Changed requests wait for an outstanding older computation and discard its result; closing a document drops its tracked work. Worker panics become errors. Failure to create workers, a disconnected worker or an individual window beyond the reservation limit falls back to the synchronous path and logs the reason. Nested group rendering and wasm stay synchronous.

While inputs are pending, mapped effect passes use zero opacity. Completion invalidates the affected display rectangles independently of document history. The live canvas keeps requesting frames while jobs are pending. The default CPU shape and distance-field builders are the existing exact implementations. An opt-in interactive Euclidean path is described below.

Set `PHOTOCRAFT_ASYNC_EFFECTS=0` before launch to restore synchronous effect inputs. Native headless GPU compositors remain synchronous unless callers explicitly enable deferred effects.

Scope: W7 step 1 implemented through a private L3 worker queue because the GPU crate cannot depend on the L5 engine job scheduler. W7 step 2 has an opt-in bounded GPU jump-flood implementation; its precision and practical performance remain unverified. GPU map passes, upload time, planning, nested group evaluation and over-limit fallback can still occupy a frame. No frame-time or convergence target is claimed.

Validation: `cargo check -p photocraft-gpu -p photocraft-ui-egui` passed on native Windows. Full build, wasm and layer checks remain pending integration. Tests, benchmarks and measurements deliberately skipped at the user's explicit request. No UI smoke test has been performed.


## Optional GPU Euclidean fields (step 2)

Set `PHOTOCRAFT_GPU_DISTANCE=1` before launch to enable native interactive jump flooding. The default remains exact CPU fields. Only `Outside`, `Inside` and `OutsideInverse` with reach at least 64 pixels are eligible; every stroke kind keeps its existing exact CPU chamfer metric. The CPU worker supplies compose's exact shape and any ineligible fields. Export/synchronous and nested compositors stay exact; toggling asynchronous mode clears effect caches so an export cannot reuse approximate fields.

The GPU initializes seed coordinates from the same `0.5 / 255` alpha threshold, propagates nearest seeds with decreasing power-of-two steps plus a final unit refinement (JFA+1), and applies the existing `-0.5` edge offset, inverse-alpha convention and outside nearest-seed coverage correction. Empty seed sets retain the EDT's `sqrt(1e20)` distance convention. Coordinates tie by column then row. Nearest-seed search is approximate: no maximum error, 0.5-pixel bound, 1/255 coverage bound, Photoshop parity or visible equivalence is established. This opt-in is not a precision guarantee.

No CPU readback or device wait occurs. All GPU allocations, dispatches and copies run on the render thread. Two 8-byte-per-pixel coordinate buffers and a padded R32Float output buffer feed a 256-byte-row-aligned buffer-to-texture copy into the existing field texture. A dedicated command buffer is validated before submission and precedes the render encoder on the same queue; a rejected encoder is dropped without poisoning the render encoder. Shape uploads are queued first. Full-region field recomputation also invalidates the entire downstream effect-map region because approximation changes are not guaranteed to respect the exact field's damage radius.

Eligible regions contain 65,536?2,097,152 pixels and have no dimension above 4096. Device storage/workgroup/buffer limits are checked. The largest dimension permits at most 13 jump passes, plus initialization and final encoding. The per-compositor-frame allowance is 96 MiB of cumulative scratch-buffer reservations and 250 million conservative pixel/neighbour visits across all fields, including failed reservations. Oversized/ineligible work, unsupported limits, pipeline/allocation/encoding errors, and validation that cannot complete immediately use the exact CPU field builder. When an eligible async request omitted its CPU field but GPU dispatch later fails or exceeds the frame allowance, fallback computation runs synchronously and can still occupy the frame. Device loss after submission follows the application's existing device recovery path; there is no blocking completion probe.
